# ACCP.AI — بوت تلجرام قابل للنشر على Railway

هذه النسخة مبنية على **ACCP_AI_Adaptive_Interview_V1** نفسه. تحافظ على:

- الإفادة الأولى برسالة واحدة ثم الأسئلة التكيفية (حتى ستة، مع إنهاء مبكر إن كفت المعلومات).
- استخراج الوقائع المرتبطة باقتباسات من كلام المستخدم وتطبيق القواعد الاحتياطية للتصنيف والنفي.
- مؤشر شدة **تجريبي وغير معاير**، ومسارات المراجعة وإرشادات الخلاف البسيط.
- تقرير Markdown كامل يُرسل كملف عبر تلجرام.
- خيار اختياري صريح لإنشاء **مسودة بلاغ للمراجعة** في الحالات المرتفعة فقط، ولا يوجد إرسال رسمي لأي جهة.

## التصور التقني

`Telegram على الهاتف أو اللابتوب → Python bot على Railway → API النموذج المستضاف → engine.py → Telegram`.

**لا يتم تحميل أو تشغيل Ollama أو Qwen المحلي على Railway.** للمسار السحابي يستخدم النموذج المتاح لدى مقدم الخدمة. النموذج المقترح هو `qwen/qwen3.5-9b` على OpenRouter، وليس النموذج المحلي `qwen3.5:4b-q4_K_M` نفسه. التبديل قد يغير نتائج التصنيف؛ اختبره قبل العرض ولا تعد بنتيجة ثابتة.

يستعمل النظام `long polling` في **خدمة Railway واحدة (Replica=1)**؛ لا تحتاج دومين أو ويب هوك ولا منفذ HTTP. تجنب تشغيل نسخة محلية ونسخة Railway في وقت واحد بنفس توكن تلجرام.

## الخطوة 1 — أنشئ بوت تلجرام

1. افتح `@BotFather` في تلجرام.
2. أرسل `/newbot` وحدد اسمًا واسم مستخدم ينتهي بـ `bot`.
3. احفظ **رمز البوت TOKEN** في مكان آمن. لا تضعه في GitHub أو صور العرض ولا ترسله في المحادثات.

## الخطوة 2 — جهّز مفتاح نموذج مستضاف

1. افتح https://openrouter.ai/ وابحث عن **API Keys**.
2. أنشئ مفتاح API خاصًا بالاختبار.
3. اسم النموذج المقترح: `qwen/qwen3.5-9b`، ويقبل `response_format` من نوع JSON schema بحسب صفحة النموذج. **تحقق من السعر الحالي والحدود قبل التشغيل**.
4. تُرسل إفادات الاختبار إلى خدمة الاستدلال الخارجية؛ **لا تستخدم بيانات شخصية أو شكاوى حقيقية** في العرض.

يمكن استخدام مزوّد آخر يدعم `/chat/completions` وواجهة OpenAI المتوافقة، بعد تغيير `LLM_BASE_URL` و`LLM_MODEL` و`LLM_API_KEY`، لكن اختبارنا موجّه إلى OpenRouter.

## الخطوة 3 — ارفع المشروع إلى GitHub

- فك ضغط ZIP. يجب أن تكون ملفات `Dockerfile` و`telegram_bot.py` و`railway.toml` في **جذر المستودع**، وليس داخل مجلد إضافي.
- أنشئ مستودع GitHub **خاصًا (Private)** باسم مثل `accp-ai-telegram-demo`.
- من PowerShell داخل مجلد المشروع (بعد إنشاء المستودع الفارغ على GitHub):

```powershell
git init
git add .
git commit -m "ACCP.AI Telegram Railway demo"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/accp-ai-telegram-demo.git
git push -u origin main
```

لا ترفع `.env` أو أي مفاتيح أو تقارير حقيقية. `.gitignore` مُجهّز لاستبعادها.

## الخطوة 4 — انشر على Railway

1. ادخل https://railway.com/ → **New Project** → **Deploy from GitHub repo**.
2. اختر المستودع الذي أنشأته. Railway سيكتشف `Dockerfile` تلقائيًا.
3. افتح الخدمة → **Variables**، وأضف المتغيرات التالية:

| المتغير | القيمة / الوصف |
|---|---|
| `TELEGRAM_BOT_TOKEN` | الرمز من BotFather (سري) |
| `ALLOWED_TELEGRAM_IDS` | رقم حسابك على تلجرام؛ يمكن إضافة أرقام مفصولة بفاصلة `123456,789012` |
| `LLM_PROVIDER` | `cloud` |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` |
| `LLM_API_KEY` | مفتاح API من مقدم النموذج (سري) |
| `LLM_MODEL` | `qwen/qwen3.5-9b` |
| `LLM_JSON_MODE` | `json_schema` |
| `LLM_TIMEOUT_SECONDS` | `90` |

4. إن لم تكن تعرف Telegram ID، ضع `ALLOWED_TELEGRAM_IDS=1` موقتًا. بعد النشر، افتح البوت في محادثة **خاصة** وأرسل `/id`. سيُظهر معرفك، ثم ضع الرقم بدل `1` على Railway وأعد نشر التغيير.
5. اضغط **Deploy** لتطبيق المتغيرات. اترك **Replicas=1** ولا تنشئ دومين؛ خدمة البوت لا تحتوي على ويب سيرفر.
6. افتح **Deploy Logs** وابحث عن `ACCP.AI Telegram polling worker started`. هذه إشارة بدء للعملية، لكنها لا تؤكد وصول رسالة نموذج خارجية. اختبار `/new` وإرسال إفادة يختبر الطرفين معًا.

> **هام:** بعض خطط Railway لها حدود موارد أو تكلفة اشتراك واستهلاك؛ تشغيل worker بشكل مستمر قد يستهلك رصيدًا. راقب Usage/Billing ولا تعتمد على «مجاني بالكامل».

## الخطوة 5 — التجربة في تلجرام

- `/start` أو `/new` — بدء مقابلة اختبارية جديدة.
- أرسل **إفادة اصطناعية برسالة واحدة**.
- أجب عن السؤال الذي يظهر، ثم السؤال التالي (حتى ستة، ويمكن الانتهاء أبكر).
- بعد الانتهاء تصلك **نتيجة موجزة** وتقرير Markdown كامل كملف.
- `/report` — إعادة إرسال التقرير.
- `/status` — حالة الجلسة.
- `/cancel` — إلغاء الجلسة السابقة.
- `/id` — معرف الحساب لإضافته إلى قائمة السماح.
- `/help` — عرض الأوامر.

### مثال قصير جاهز للعرض (اصطناعي)

> أمس صار نقاش بيني وبين جاري بسبب موقف السيارة. ما هددني ولا اعتدى عليّ وما صار ضرر. بعد ما حرك السيارة انتهى الموضوع، وأنا مش بخطر الآن. بدي نصائح حتى ما يتكرر سوء الفهم.

قد يختلف عدد الأسئلة والتصنيف بحسب النص واستجابة النموذج. لا تستخدم الأمثلة كدليل على دقة إحصائية.

## الاختبارات

من داخل المشروع:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

اختبارات الدولة (القواعد، المقابلة، مسارات البلاغ، طلب API مع شبكة وهمية) لا تتطلب مفاتيح حقيقية. تم إجراء **76 اختبارًا محليًا بلا اتصال خارجي**. لم نختبر هنا بوت تلجرام الحقيقي أو مفتاح OpenRouter على شبكة حية.

## سياسة العرض والقيود الأمنية

- الخدمة **خاصة**: لا تُقبل الرسائل إلا من حسابات رقم `ALLOWED_TELEGRAM_IDS`، وفي المحادثات الخاصة فقط. `/id` متاح حتى تتمكن من معرفة المعرف.
- لا تُسجّل رسائل الشكوى في Logging الخاص بالبرنامج. لكن **تلجرام ومقدم النموذج الخارجي وRailway يعالجون البيانات المرسلة**؛ لا تفترض السرية المناسبة للشكاوى الفعلية.
- جلسات المستخدمين وتقاريرهم محفوظة **في ذاكرة العملية فقط**؛ قد تختفي عند إعادة النشر أو إعادة تشغيل الخدمة. ملف التقرير يُرسل فورًا للمستخدم في تلجرام ويستطيع حفظه. هذا الخيار للتجارب، وليس قاعدة بيانات إنتاجية.
- يرفض البوت الصور والملفات والصوت حاليًا؛ النصوص فقط.
- لا توجد مراجعة بشرية آلية حقيقية، ولا تكامل مع جهات رسمية، ولا إرسال بلاغات.
- مخرجات الشدة ليست احتمالات إحصائية أو أحكامًا قانونية. أخطاء النفي والتصنيف ما زالت ممكنة.
- **فشل API:** إذا رفض المزود صيغة JSON أو انتهت المهلة، يعرض النظام نقص التقييم بدل اختراع نتيجة موثوقة. جرّب تبديل `LLM_JSON_MODE=json_object` أو مزودًا متوافقًا مع المخطط.
- المصادقة والخصوصية وموثوقية الاستدلال تحتاج مراجعة إضافية قبل التعامل مع بيانات واقعية.

## إذا تعطل البوت

- Deployment fails: راجع `Deploy Logs`، ومتغيرات `TELEGRAM_BOT_TOKEN`, `ALLOWED_TELEGRAM_IDS`, `LLM_MODEL`, `LLM_API_KEY`.
- `/id` يعمل و`/start` لا يعمل: أضف معرفك إلى `ALLOWED_TELEGRAM_IDS` بدقة وأعد تطبيق المتغيرات.
- `HTTP 401`: مفتاح خدمة النموذج غير صحيح أو منتهي.
- `HTTP 404`: اسم النموذج أو عنوان `LLM_BASE_URL` غير صحيح.
- `HTTP 400`: قد لا يدعم المزود `json_schema`؛ جرّب `LLM_JSON_MODE=json_object`.
- `HTTP 429`: وصلت إلى حد الطلبات أو الرصيد/الحصة.
- `Conflict`/`getUpdates`: يوجد أكثر من نسخة polling تعمل بنفس Token؛ أوقف النسخ الزائدة، ولا تشغّل البوت من PowerShell بالتزامن مع Railway.
- اختفت الجلسة: طبيعي بعد إعادة النشر لأن الحالة مخزنة في الذاكرة؛ أرسل `/new`.
