# تشغيل ACCP.AI على Railway

تاريخ مراجعة الإعدادات والوثائق: 24 أكتوبر 2026. تم اختبار التطبيق محليًا مع محاكاة الخدمات. **لم يُنفذ نشر حي أو بناء Docker فعلي في بيئة التسليم.**

## 1. رفع المشروع

فك `ACCP_AI_PRODUCTION_DEMO_FINAL.zip`. افتح مجلد المشروع وارفع محتوياته إلى جذر مستودع GitHub خاص؛ يجب أن يظهر `Dockerfile` و`railway.toml` مباشرة في جذر المستودع.

يمكن استخدام واجهة GitHub لرفع الملفات، أو تنفيذ:

```powershell
git init
git add .
git commit -m "ACCP.AI production demo"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

استبدل اسم الحساب والمستودع. لا ترفع `.env` أو بيانات حالات حقيقية. `.gitignore` يستبعد قاعدة البيانات وتقارير التشغيل المحلية.

## 2. إنشاء الخدمة والقرص الدائم

في Railway اختر مشروعًا جديدًا ثم النشر من مستودع GitHub. اختر المستودع. أضف Volume للخدمة واجعل Mount Path هو `/data`.

اترك عدد النسخ **1**، واترك Start Command دون تجاوز؛ التشغيل محدد في Docker ENTRYPOINT. لا تضف دومينًا أو HTTP healthcheck: هذه عملية Long Polling وليست خادم ويب. أوقف أي نسخة أخرى تستخدم توكن البوت نفسه.

يبدأ `docker_entrypoint.py` بصلاحية root فقط لإسناد ملكية `/data`، ثم يخفض المستخدم والمجموعة إلى 10001 قبل استيراد البوت. لا يحتاج تعيين `RAILWAY_RUN_UID=0` يدويًا مع Dockerfile المرفق. افحص صلاحيات Volume عند أول نشر؛ هذا المسار لم يُجرّب حيًا هنا.

Railway يوثق قيود Volumes، ومنها عدم استخدام النسخ المتعددة مع القرص نفسه وفترة توقف قصيرة أثناء إعادة النشر. لذلك اخترنا SQLite لعرض صغير بعملية واحدة. [توثيق Volumes](https://docs.railway.com/volumes/reference).

## 3. المتغيرات

أضفها في Variables الخاصة بالخدمة:

| المتغير | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | التوكن الحقيقي من BotFather |
| `ALLOWED_TELEGRAM_IDS` | معرفك الحقيقي، أو قائمة أرقام مفصولة بفواصل |
| `LLM_PROVIDER` | `cloud` |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` أو عنوان مزود متوافق موثوق |
| `LLM_API_KEY` | مفتاح API الحقيقي |
| `LLM_MODEL` | معرف نموذج متاح في حسابك ويدعم JSON؛ اختره من كتالوج المزود |
| `LLM_JSON_MODE` | `auto` |
| `LLM_TIMEOUT_SECONDS` | `35` |
| `LLM_MAX_ATTEMPTS` | `3` |
| `DATA_DIR` | `/data` |
| `DATA_RETENTION_HOURS` | `24` |
| `MAX_PARALLEL_LLM` | `3` |

لا تضع معرف سماح وهميًا مثل 1. إذا لم تعرف معرفك، اترك `ALLOWED_TELEGRAM_IDS` فارغًا في النشر الأول؛ يرفض البوت جميع المقابلات والتقارير ويسمح فقط بمعرفة المعرف عبر `/id`. أضف الرقم الذي تحصل عليه وأعد النشر.

لا يوجد اسم نموذج مفروض أو ادعاء بأن نموذجًا بعينه اختُبر. دعم Structured Outputs يعتمد على النموذج والمزود. يستخدم `auto` مخطط JSON أولًا ثم يتراجع مرة محدودة إلى JSON Object عند خطأ صريح بعدم دعم الصيغة، ويظل تحقق Pydantic إلزاميًا. [توثيق OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).

## 4. التحقق قبل العرض

1. تأكد من نجاح البناء وظهور `worker_started` في السجل.
2. افتح محادثة خاصة مع البوت وأرسل `/id` ثم `/start`.
3. استخدم مثال الخلاف البسيط في `examples/SCENARIOS_AR.md`. يجب ألا يفترض تهديدًا منفيًا.
4. استخدم مثال الابتزاز دون دفع ودون نشر، وأجب عن الأسئلة ثم جرّب رفض المسودة وإنشاءها في قضيتين منفصلتين.
5. ابدأ مقابلة، نفّذ Restart للخدمة، ثم `/status`. يجب استعادة السؤال نفسه. قارن رقم القضية.
6. اختبر حسابًا خارج قائمة السماح؛ يجب ألا يحصل على مقابلة أو تقرير.
7. جرّب `/report` للتنزيل و`/reset` للحذف. راقب أخطاء API وحدود الإنفاق.

هذه خطوات تحقق حي متبقية، وليست نتائج نجاح مدعاة في التسليم. GitHub Actions المرفق يشغّل الاختبارات وبناء Docker عند رفع المستودع، ولم تُشغّل هذه المهمة على GitHub أثناء التجهيز.

## التكلفة والخدمات

لا تحتاج PostgreSQL لهذه النسخة. تحتاج خدمة التطبيق وVolume ومزود LLM. بحسب صفحة Railway الرسمية يوم المراجعة، Hobby يبدأ من 5 دولارات شهريًا تتضمن 5 دولارات من الاستخدام؛ يُحاسب الاستخدام الزائد. تكلفة Volume المنشورة 0.15 دولار لكل GB شهريًا، مع تكاليف الموارد الأخرى. هذه ليست فاتورة متوقعة أو ضمان سعر؛ راجع حسابك قبل النشر. [أسعار Railway](https://docs.railway.com/pricing/plans).

تكلفة LLM منفصلة وتعتمد على النموذج والتوكنات. المعتاد طلب واحد للإفادة وطلب لكل إجابة تحتوي معلومات لغوية جديدة؛ الإجابات القصيرة المباشرة لا تستدعي النموذج، ولا يوجد طلب مستقل لإعادة توليد التقرير. إعادة المحاولة قد تضيف طلبات عند تعطل المزود.

إذا احتجت لاحقًا عدة نسخ أو Webhooks أو مستخدمين كثيرين، انقل الجلسات إلى PostgreSQL مع قفل موزع وطابور تسليم. PostgreSQL عندها خدمة إضافية باستهلاك مستقل؛ غير مطلوبة أو مدعاة الاختبار هنا.

## الأعطال الشائعة

- خطأ 401 من النموذج: راجع المفتاح، لا توجد إعادة محاولة تلقائية لهذا الخطأ.
- خطأ النموذج أو JSON: راجع `LLM_MODEL` و`LLM_JSON_MODE`، ثم راجع التقرير الذي يوسم فشل الاستخراج.
- خطأ Volume: تأكد أن Mount Path وDATA_DIR كلاهما `/data`.
- Conflict من Telegram: أوقف النسخ الأخرى المستخدمة للتوكن نفسه.
- عدم الرد: راجع قائمة السماح والمحادثة الخاصة وسجل نوع الخطأ فقط. لا تنشر السجلات المحتوية على مفاتيح من أدوات خارج التطبيق.
