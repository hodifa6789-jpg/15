# إعداد Telegram وتجربة العرض

1. افتح الحساب الرسمي `@BotFather` في Telegram وأرسل `/newbot`.
2. اختر اسمًا واسم مستخدم للبوت، واحفظ التوكن داخل Railway Variables باسم `TELEGRAM_BOT_TOKEN`.
3. انشر وفق [دليل Railway](RAILWAY_DEPLOYMENT_AR.md)، ثم افتح البوت في **محادثة خاصة**.
4. أرسل `/id`. ضع الرقم في `ALLOWED_TELEGRAM_IDS` وأعد النشر.
5. أرسل `/start` ثم إفادة اصطناعية واحدة كاملة.

| الأمر | السلوك |
|---|---|
| `/start` | يبدأ جلسة أو يرشد لمتابعة الجلسة الحالية دون محوها |
| `/new` | يستبدل القضية الحالية بقضية جديدة؛ نزّل التقرير قبل ذلك |
| `/help` | عرض المساعدة |
| `/status` | حالة المقابلة ورقم القضية ونص السؤال المحفوظ |
| `/report` | ملفات Markdown وHTML وJSON، والمسودة إن سبق طلبها |
| `/cancel` | إلغاء وحذف محتوى الجلسة المحلية |
| `/reset` | حذف محتوى الجلسة المحلية |
| `/id` | معرف المستخدم؛ متاح دون السماح بالمقابلة |

تظهر أزرار للحالة والتقرير، وأزرار موافقة/تجاوز عند عرض المسودة. يرتبط زر المسودة برقم القضية حتى لا تؤثر أزرار قضية قديمة على قضية جديدة.

الحد الأقصى للإفادة 3000 حرف وللإجابة 1500. البوت يقبل النصوص فقط؛ لا ترسل صورًا أو وثائق حساسة. تقسيم الردود يراعي طول UTF-16 المستخدم مع الرموز التعبيرية.

قد تنتهي المقابلة دون أي سؤال إذا كانت معلومات الخلاف المنتهي وهدفك واضحة. ستة أسئلة سقف وليست عددًا مطلوبًا. إذا أرسلت إجابتين بسرعة قبل عرض السؤال التالي، يطلب البوت إعادة إرسال الثانية بعد قراءة السؤال بدل ربطها بسؤال لم تره.

لا يوجد إرسال إلى شرطة أو جهة حكومية. الموافقة تنشئ **مسودة للمراجعة فقط**. ولا ينشئ البوت المسودة تلقائيًا في مسار إرشادات السلامة الفورية.

إلغاء الجلسة يمحو محتواها من قاعدة التطبيق ويحتفظ مؤقتًا بمعرفات التحديثات لمنع إعادة تنفيذ الرسائل القديمة. لا يحذف ملفاتك المنزلة أو نسخ Telegram أو بيانات المزود الخارجي. هذه نسخة عرض لحالات اصطناعية.
